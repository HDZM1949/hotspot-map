# 🌍 世界热点地图（HotspotMap）项目规划书

> 开源 · 实时 · 可自部署 —— 打开网页即可看到世界各地正在发生的热点事件

---

## 1. 项目概述

**一句话定位**：一个开源的实时全球热点地图应用 —— 以世界地图为核心界面，聚合全球多源实时数据（新闻事件、地震、气象灾害等），以「热点」的形式呈现，支持按分类、时间、区域筛选，并通过 WebSocket 实时更新。

**目标用户**：新闻从业者、资讯爱好者、数据分析爱好者、开源贡献者。

**核心价值**：

- 🗺️ 一张图看世界：聚合新闻、灾害、气象等多源数据，统一为带坐标、分类、热度分数的「热点事件」
- ⚡ 实时：采集 → 处理 → 推送全链路自动化，15 分钟级（甚至分钟级）更新
- 🔓 全开源：MIT 协议、可自部署、默认数据源全部免费且无需 API Key
- 🧩 可扩展：数据源可插拔，社区可贡献任意新源

**MVP 范围（第一个可发布版本）**：

1. 世界地图 + 热点聚合点 + 热力图两种呈现模式
2. 接入 3 个免费数据源：GDELT（全球新闻）、USGS（地震）、Open-Meteo（气象预警）
3. 分类 / 时间 / 区域筛选
4. 事件详情卡片（标题、摘要、来源链接、时间线）
5. WebSocket 实时增量推送
6. Docker Compose 一键部署

## 2. 系统架构

```
┌────────────────────────── 数据采集层 ──────────────────────────┐
│  GDELT(15min)  USGS(5min)  Open-Meteo(10min)  Reddit  RSS ...  │
└───────────────────────────────┬─────────────────────────────────┘
                                ▼
┌────────────────────────── 处理层 ──────────────────────────────┐
│  归一化 → 地理编码 → 去重 → 分类 → 热度评分                     │
└───────────────────────────────┬─────────────────────────────────┘
                                ▼
┌────────────────────────── 存储层 ──────────────────────────────┐
│   PostgreSQL 16 + PostGIS（事件/提及）   Redis（缓存/限流/Pub-Sub）│
└───────────────┬──────────────────────────────────┬─────────────┘
                ▼                                  ▼
┌────────────────────────── 服务层 ──────────────────────────────┐
│   REST API（查询/统计/健康）       WebSocket 网关（实时广播）    │
└───────────────┬──────────────────────────────────┬─────────────┘
                └────────────────┬─────────────────┘
                                 ▼
┌────────────────────────── 前端层 ──────────────────────────────┐
│  地图渲染(MapLibre GL) + 聚合(supercluster) + 筛选/详情 + 实时订阅│
└─────────────────────────────────────────────────────────────────┘
```

**实时链路（核心时序）**：

```
采集器拉取 → 处理器清洗 → 写入 Postgres → Redis Pub/Sub → API 广播 → WebSocket → 前端增量合并
```

## 3. 技术栈

### 前端

| 分类     | 选型                         | 选型理由                                  |
| -------- | ---------------------------- | ----------------------------------------- |
| 框架     | React 18 + TypeScript + Vite | 生态成熟、构建快、类型安全                |
| 地图引擎 | **MapLibre GL JS**           | 开源免费、无需 token（Mapbox 需付费 Key） |
| 点聚合   | **supercluster**             | 高性能点聚合，支撑数万热点流畅渲染        |
| UI       | Tailwind CSS + shadcn/ui     | 快速搭建、可定制、自带暗色主题            |
| 状态管理 | Zustand                      | 轻量、无样板代码                          |
| 实时通信 | WebSocket（原生封装）        | 双向实时推送，无重依赖                    |

### 后端

| 分类       | 选型                                    | 选型理由                                       |
| ---------- | --------------------------------------- | ---------------------------------------------- |
| API 框架   | Node.js + **Fastify** + TypeScript      | 高性能、插件化、与前端共享类型                 |
| ORM / 迁移 | Drizzle ORM                             | 轻量、类型安全、SQL 友好                       |
| 校验       | Zod                                     | 运行时校验 + 类型推导，前后端复用同一套 schema |
| 任务调度   | node-cron（采集器）/ BullMQ（可选队列） | 定时采集、失败重试                             |

### 数据层

| 分类      | 选型                        | 选型理由                                 |
| --------- | --------------------------- | ---------------------------------------- |
| 数据库    | PostgreSQL 16 + **PostGIS** | 空间索引支撑矩形区域（bbox）毫秒级查询   |
| 缓存/消息 | Redis 7                     | Pub/Sub 实时广播、去重缓存、限流         |
| 搜索      | PostgreSQL 全文检索         | MVP 够用；用户量大后可平滑换 Meilisearch |

### 基础设施

| 分类   | 选型                                             |
| ------ | ------------------------------------------------ |
| 容器化 | Docker + docker-compose（一键起全部服务）        |
| CI/CD  | GitHub Actions（lint → test → build → 镜像）     |

## 4. 数据源策略（开源免费优先）

| 数据源          | 内容                               | 更新频率       | API Key | 自带坐标 | 备注                             |
| --------------- | ---------------------------------- | -------------- | ------- | -------- | -------------------------------- |
| **GDELT 2.0**   | 全球新闻事件（含经纬度、主题分类） | 15 分钟        | 无      | ✅       | **核心源**，公开数据集，无需注册 |
| USGS Earthquake | 全球地震                           | 实时（5 分钟） | 无      | ✅       | GeoJSON Feed，权威               |
| Open-Meteo      | 天气 / 灾害预警                    | 10 分钟        | 无      | ✅       | 需 CC-BY 4.0 署名                |
| GDACS           | 洪水/台风/野火等灾害               | 数小时         | 无      | ✅       | 联合国运营                       |
| Reddit          | 社区热点（无坐标）                 | 10 分钟        | 免费层  | ❌       | 需地理编码兜底                   |
| 自定义 RSS      | 任意新闻源                         | 可配置         | 无      | ❌       | 需地理编码兜底                   |

**关键设计**：

- 无坐标的数据源 → 交给处理器中的地理编码模块（Nominatim，遵守 1 req/s 限流，结果缓存到 Redis）
- 每个源记录 `last_fetched` / `last_error`，失败指数退避重试，保证管道健壮性
- 严格遵守各源 ToS：Open-Meteo 署名、Reddit 限流、GDELT 免费公开可商用

## 5. 数据模型（核心表）

```sql
-- 核心表：规范化事件（一个「热点」）
CREATE TABLE events (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  fingerprint   TEXT UNIQUE NOT NULL,      -- 去重指纹（标题规范化 + 坐标 + 时间哈希）
  title         TEXT NOT NULL,
  summary       TEXT,
  category      TEXT NOT NULL,             -- disaster|conflict|politics|economy|tech|sports|science|weather|other
  severity      REAL,                      -- 严重度 0~1
  heat_score    REAL NOT NULL DEFAULT 0,   -- 热度分（前端排序/渲染依据）
  lat           DOUBLE PRECISION NOT NULL,
  lon           DOUBLE PRECISION NOT NULL,
  country_code  CHAR(2),
  occurred_at   TIMESTAMPTZ NOT NULL,
  first_seen_at TIMESTAMPTZ NOT NULL,
  last_seen_at  TIMESTAMPTZ NOT NULL,
  mention_count INT NOT NULL DEFAULT 1,    -- 被多少个来源提及
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

-- 空间索引：bbox 区域查询的核心
CREATE INDEX idx_events_geo ON events
  USING GIST (ST_SetSRID(ST_MakePoint(lon, lat), 4326));
CREATE INDEX idx_events_heat ON events (heat_score DESC);
CREATE INDEX idx_events_time ON events (occurred_at DESC);

-- 来源提及表（一个事件可被多个源报道，合并热度）
CREATE TABLE event_mentions (
  id         BIGSERIAL PRIMARY KEY,
  event_id   UUID NOT NULL REFERENCES events(id) ON DELETE CASCADE,
  source     TEXT NOT NULL,                -- gdelt | usgs | openmeteo | ...
  source_id  TEXT NOT NULL,                -- 源内唯一 ID
  url        TEXT,
  title      TEXT,
  fetched_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (source, source_id)               -- 幂等写入，天然防重复采集
);
```

## 7. 模块功能描述

### ① `apps/web` — 前端地图应用

| 子模块              | 职责                                                                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `features/map`      | MapLibre GL 初始化与销毁、底图切换（OSM / MapTiler / 天地图）、视图状态（中心点/缩放级别）管理、聚合模式 ↔ 热力图模式切换                 |
| 热点渲染层          | 基于 supercluster 动态聚合：低缩放级别显示聚合圆（数量 + 热度色阶），高缩放级别展开为单个热点标记；热度分映射到颜色与大小                 |
| 热力图模式          | 按 `heat_score` 渲染 heatmap 图层，直观呈现全球热度分布                                                                                   |
| `features/filters`  | 分类（多选）、时间范围（最近 1h/24h/7 天）、区域（当前视野 bbox）、关键词搜索；筛选条件同步到 URL（可分享链接），驱动 REST 查询与 WS 订阅 |
| `features/events`   | 侧栏事件列表（按热度排序）、点击热点弹出详情卡片（标题/摘要/分类/坐标/首次发现时间/来源链接列表）、事件详情页                             |
| `features/realtime` | WebSocket 客户端：心跳保活、断线指数退避重连、重连后拉取增量补偿；收到新增/更新/过期消息后增量合并到图层与列表，新热点带动画高亮          |
| `store`             | Zustand：筛选条件、地图视图、事件 LRU 缓存（限制内存占用）、UI 状态                                                                       |
| `services`          | REST 客户端（fetch 封装 + 取消请求）、WS 客户端（自动重连 + 订阅管理）                                                                    |
| i18n                | 中 / 英双语（后续可扩展）                                                                                                                 |

### ② `apps/api` — 后端 API 与实时网关

| 子模块     | 职责                                                                                                                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `events`   | REST 查询：`GET /api/events?bbox=...&from=&to=&category=&q=&sort=heat&limit=&cursor=`；bbox 走 PostGIS 空间索引（毫秒级），q 走全文检索，游标分页；`GET /api/events/:id` 返回详情 + 提及列表 |
| `realtime` | WebSocket `/ws/events` 网关：客户端可订阅频道（全部 / 按分类 / 按区域）；订阅 Redis `events:new` 频道，把新增/更新/过期事件广播给匹配订阅的连接；连接数统计与限流                            |
| `stats`    | `GET /api/stats/summary`：事件总量、分类分布、24 小时趋势、当前 TOP10 热点                                                                                                                   |
| `health`   | `/healthz`（存活）、`/readyz`（就绪，检查 PG/Redis 连接），供 Docker 健康检查与编排使用                                                                                                      |
| `common`   | 请求日志、统一错误响应、Redis 滑动窗口限流、CORS、Zod 校验管道                                                                                                                               |

### ③ `packages/shared` — 共享包

前后端 + 采集器 + 处理器共用的类型与规则，杜绝「三处各写一份」的漂移问题：

- 类型定义：`Event`、`Mention`、`Category`、`Source`、`FilterQuery`、`WSMessage`（增量推送协议）
- 常量：分类枚举、数据源元数据（名称、更新频率、版权说明、图标）
- Zod schema：API 入参校验、采集器 RawEvent 产出校验、处理器输出校验

### ④ `packages/ingesters` — 数据采集器（独立进程）

| 子模块                   | 职责                                                                                                                                                            |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scheduler`              | node-cron 按各源频率调度；并发控制、超时熔断、指数退避重试；把每个源的 `last_success` / `last_error` / `item_count` 写入 Redis，供 `/api/health` 与运维看板展示 |
| `sources/gdelt`          | 每 15 分钟增量拉取 GDELT 2.0，解析 CSV，过滤带坐标事件，映射为统一 RawEvent                                                                                     |
| `sources/usgs`           | 每 5 分钟增量拉取 USGS GeoJSON feed，按 `updated` 时间增量                                                                                                      |
| `sources/openmeteo`      | 每 10 分钟拉取气象预警 GeoJSON                                                                                                                                  |
| `sources/reddit` / `rss` | 可插拔扩展源，产出无坐标事件（由处理器地理编码兜底）                                                                                                            |
| `pipeline`               | 所有采集器统一出口：RawEvent → Zod 校验 → 投递给处理器；与数据源解耦，新增源只需实现一个 fetch 函数                                                             |

### ⑤ `packages/processor` — 数据处理管道

| 子模块      | 职责                                                                                                                                                                           |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `normalize` | RawEvent → Event 草案：字段清洗、时区统一为 UTC、坐标合法性校验（纬度 ±90 / 经度 ±180）                                                                                        |
| `geocode`   | 对无坐标事件调用 Nominatim 解析地点文本；1 req/s 限流、Redis 缓存结果、失败降级（国家/地区级坐标或丢弃）                                                                       |
| `dedupe`    | 两层去重：① `(source, source_id)` 幂等防重复采集；② 跨源相似检测（标题规范化 + 编辑距离 + 坐标距离 + 时间窗口），命中则合并 `mention_count`、更新 `last_seen_at`、补充提及链接 |
| `classify`  | 多语言关键词规则库分类：disaster / conflict / politics / economy / tech / sports / science / weather / other                                                                   |
| `score`     | 热度评分 = 源权重 × 时效衰减（指数衰减） × 关键词强度 × log(mention_count)，归一化 0~100                                                                                       |
| `writer`    | 批量 upsert 入库，成功后 PUBLISH Redis `events:new` 触发实时推送                                                                                                               |

### 基础设施

| 模块                       | 职责                                                                                                       |
| -------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `infra/docker-compose.yml` | 5 个服务：postgres（postgis 镜像）、redis、api、web（nginx 静态托管 + 反代）、ingester，一条命令本地起全部 |
| `infra/postgres/init.sql`  | 建表 + PostGIS 扩展 + 空间/热度/时间索引                                                                   |
| CI                         | GitHub Actions：`pnpm install → lint → typecheck → test → build`，main 分支构建 Docker 镜像并推送 GHCR     |
| `docs/`                    | 架构说明、数据源版权清单（Open-Meteo CC-BY 署名等）、自部署教程、贡献指南                                  |

| 本地开发 | `docker-compose up` 一键起 PG + Redis；`pnpm dev` 并行起 API / Web / Ingester（Turborepo）       |
| 生产     | Docker 镜像（api / web / ingester）+ 任意云主机或 VPS；nginx 反代 + HTTPS；数据卷持久化 PG/Redis |

## 10. 开发路线图

| 里程碑                 | 内容                                                                                                                       | 预估   |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------- | ------ |
| **M1 骨架 + 核心链路** | 仓库脚手架（pnpm workspace + turbo）、docker-compose、GDELT 采集器、最小处理器管道、前端地图 + 聚合点渲染（REST 全量拉取） | 2~3 周 |
| **M2 多源与数据质量**  | USGS / Open-Meteo 接入、去重 / 分类 / 热度评分完善、事件详情卡片                                                           | 2 周   |
| **M3 实时化**          | Redis Pub/Sub + API WS 网关、前端实时订阅与重连补偿、筛选面板（分类/时间/区域）                                            | 2 周   |
| **M4 打磨与发布**      | 搜索、热力图模式、统计模块、文档、CI、Docker 镜像、MIT 协议、首个 Release                                                  | 2 周   |

**首版建议**：4 个里程碑完成后即发布 v1.0.0；后续可扩展：用户订阅告警、事件时间线回放、多语言摘要（LLM 翻译）、移动端适配。

## 11. 开源治理

- **协议**：MIT（代码）+ 数据源各自版权（文档中明示，如 Open-Meteo 需 CC-BY 4.0 署名）
- **协作**：README 快速开始、贡献指南、Issue/PR 模板、Code of Conduct
- **社区**：数据源适配器是天然的贡献入口（写一个 fetch 函数即可接入新源）

## 12. 风险与对策

| 风险                         | 对策                                   |
| ---------------------------- | -------------------------------------- |
| 单一数据源（GDELT）质量波动  | 多源互补 + 源健康监控 + 熔断降级       |
| 无坐标事件多                 | 地理编码兜底 + 降级为国家/地区级       |
| 重复事件（多源报道同一件事） | 跨源相似去重，合并提及                 |
| 客户端内存膨胀               | 前端 LRU 缓存 + 后端仅返回视野内事件   |
| 滥用（爬虫/恶意订阅）        | API 限流 + WS 连接数限制 + CORS 白名单 |
